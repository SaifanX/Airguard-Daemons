## 2025-05-18 - Client-Side Environment Variable Exposure via Vite `define`
**Vulnerability:** The `vite.config.ts` file was configured to globally inject the `GEMINI_API_KEY` into the client-side bundle using the `define` property. This effectively bypasses the normal protection of server-side environment variables and Vite's `VITE_` prefix constraint, directly exposing the plain-text secret to any user visiting the site.
**Learning:** In Vite, placing `process.env.SECRET` within the `define` block unconditionally serializes and bundles the secret into the frontend artifact, even if the backend uses it correctly. It creates an enormous security risk when used for sensitive API keys like LLM tokens.
**Prevention:** Never use the `define` property in `vite.config.ts` to expose sensitive keys. Instead, any operation requiring secret API keys must be shifted to a backend server or serverless action (like Convex actions with the `"use node"` directive for specific modules) so the secret remains isolated on the server.
