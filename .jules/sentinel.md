## 2025-02-28 - Insecure API Key Exposure via Vite and Client-Side AI Execution
**Vulnerability:** The Gemini API key (`GEMINI_API_KEY`) was being directly exposed to the frontend bundle via Vite's `define` configuration. Additionally, the system prompt and AI logic were executing on the client side in `services/geminiService.ts`, making it vulnerable to prompt injection and unauthorized API usage (Confused Deputy problem).
**Learning:** Vite's `define` mechanism circumvents the `VITE_` prefix rule, bundling any specified variables straight into the source. Client-side AI interactions always risk secret exposure and should never construct prompts directly using untrusted data on the client side.
**Prevention:** Never use Vite's `define` to inject secrets. Use Convex (or a similar backend) to securely store and process API keys. All prompt formatting and AI execution must happen entirely on the server-side, with the frontend only passing contextual parameters to the action.
