## 2025-03-05 - Convex Mutation Validation Bypass
**Vulnerability:** Client-provided inputs in Convex mutation handlers could bypass business logic (e.g., flight status validation) if validation checks aren't strictly enforced on the server, potentially allowing users to approve high-risk flights.
**Learning:** Mutating the `args` object directly inside Convex handlers may not be the best practice and can lead to unexpected state or issues. Additionally, relying on combinations like `if (args.riskScore > 50 && args.status === "APPROVED")` leaves gaps if the client sends a status other than "APPROVED" that should also be rejected.
**Prevention:** Always create a new object from `args` (e.g., using spread syntax `const data = { ...args }`) before applying backend-enforced overrides. Implement absolute rules on the backend (e.g., `if (data.riskScore > 50) data.status = "REJECTED";`) rather than checking specific client states, ensuring the backend is the ultimate source of truth.
