## 2025-06-04 - Vite Build Client-Side API Key Exposure
**Vulnerability:** The Gemini API key (`GEMINI_API_KEY`) was passed directly to Vite's `define` property in `vite.config.ts`, exposing the secret in plain text in the final client-side bundle. This bypasses the typical `VITE_` prefix protection and leaks the sensitive key.
**Learning:** In Vite, any value explicitly mapped using `define` will be stringified and hardcoded into the build artifacts. This causes severe open proxy or Confused Deputy vulnerabilities when using services like Google Gen AI, allowing users to extract the key by inspecting the client bundle. AI execution must occur on the backend securely, constructing context on the frontend but making the direct AI SDK request on a secure Node server.
**Prevention:** Never use Vite's `define` configuration for secrets. Keep API keys strictly in environment variables accessible only by backend (Node.js/Convex) instances. Implement the Gen AI integration in an edge/Node server function (`convex/ai.ts` with `"use node";`) using `process.env.API_KEY`, receiving only sanitized contextual arguments from the frontend.
