## 2025-03-02 - Frontend API Key Exposure
**Vulnerability:** The Gemini API Key was being explicitly bundled into the frontend client using Vite's `define` configuration (`'process.env.API_KEY': JSON.stringify(env.GEMINI_API_KEY)`), allowing any user to extract it. Furthermore, the frontend client was constructing the system instructions (which could lead to prompt injection) and communicating directly with the Google GenAI API.
**Learning:** Developers sometimes use Vite's `define` property to bypass prefix restrictions (like `VITE_`), mistakenly believing the variable remains "server-side" because it is prefixed with `process.env`. The `define` property statically replaces these occurrences in the built frontend files, completely exposing the secret. AI API keys should never be accessed or bundled into the frontend.
**Prevention:** To prevent API key exposure and prompt injection, API calls must be proxied through a secure backend (e.g., Convex Actions). The backend action must securely construct the system prompt using context strings provided by the frontend, rather than allowing the frontend to pass raw system instructions. The backend action should also resolve the API key securely (e.g., `process.env.GEMINI_API_KEY`) without exposing it to the client bundle.
