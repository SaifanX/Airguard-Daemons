## 2026-05-28 - [CRITICAL] Prevent API Key Exposure in Vite Define config
**Vulnerability:** The project's `vite.config.ts` was using the `define` block to map the sensitive `GEMINI_API_KEY` into `process.env.API_KEY` and `process.env.GEMINI_API_KEY`. This is a critical security vulnerability as it injects the raw secret directly into the client-side JavaScript bundle, allowing any user to extract it. Furthermore, the frontend was directly interacting with the Gemini SDK, exposing AI systems to Confused Deputy attacks.
**Learning:** In Vite, any value explicitly passed to the `define` configuration property is bundled and exposed in plain text in the client-side build, completely bypassing environment prefix rules such as `VITE_`.
**Prevention:** Never use Vite's `define` property for sensitive secrets. All integrations that require sensitive API keys must be proxy-routed through backend services (e.g. Convex actions). Context gathering (like `zoneContext` and `weatherContext`) should be done on the frontend and passed into the server action, which securely formats the system prompt and interacts with the AI SDK without exposing the underlying API key to the client.
