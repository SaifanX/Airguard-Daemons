## 2024-06-05 - API Key Exposure via Vite Config and Client-Side AI Generation
**Vulnerability:** The Gemini API key (`process.env.API_KEY` and `process.env.GEMINI_API_KEY`) was directly exposed to the frontend bundle through `vite.config.ts`'s `define` block. This allowed client-side generation of AI responses in `services/geminiService.ts`, exposing not only the API key but also the backend system prompts and risk assessment logic.
**Learning:** In Vite, any variable defined in the `define` configuration block will be exposed statically during the build process, bypassing the typical `VITE_` prefix protections. AI generation containing sensitive or systemic logic (like Captain Arjun/Guard-1's prompt instructions and validation) must always happen on the backend to avoid prompt injection and API key leakage.
**Prevention:** Never use the `define` block in `vite.config.ts` to expose secret variables. To avoid Confused Deputy issues or API key leakage, the AI logic should be completely moved to the backend. The frontend should initialize backend actions (e.g., using `useAction` for Convex) and pass the necessary computed context (like `weatherContext` and `zoneContext`) without passing raw keys or systemic prompts.
